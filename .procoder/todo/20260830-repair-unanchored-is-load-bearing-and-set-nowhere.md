# REPAIR_UNANCHORED is load-bearing for One Pace and is set nowhere in the repo

Status: open
Created: 2026-08-30
Severity: a merge pass run from the committed scripts SILENTLY STRIPS repairs

## Description

`repair.skips_unanchored()` refuses any card with no fansub reference unless
`REPAIR_UNANCHORED` is set (`repair.py:194`), and the flag "stays CONDITIONAL and defaults
CLOSED" by deliberate decision. One Pace has NO reference track at all — its muxed episodes
carry only our own `Dubtitles` stream, and `common.dialogue_intervals()` returns 0 intervals
— so with the gate closed EVERY card is skipped.

`REPAIR_UNANCHORED` appears in exactly two places in the whole repository, both in
`repair.py` (the read at `:285` and the use at `:194`). It is set in NO script, NO Dockerfile
and NO container env — `docker inspect dubtitle-builder` does not carry it.

Yet the live One Pace library was plainly produced with it ON. The original per-episode
summaries show real work:

    S31E01  targets=161  repaired=21  skipped_no_ref=0
    S31E02  targets=102  repaired=10  skipped_no_ref=0
    S31E03  targets=129  repaired=15  skipped_no_ref=0
    S31E06  targets=153  repaired=25  skipped_no_ref=0

`161 targets -> 21 repairs` is the exact figure `skips_unanchored`'s own docstring cites for
the gate-open experiment. So the whole season was generated by a hand-set flag that no
committed artifact records.

## Why this is worse than an undocumented setting

`repair.py` REBUILDS the srt from `conf.json` on every run. When the gate is closed every
card is skipped, nothing is repaired, and the rebuilt srt is raw ASR text. So running
`merge_pass.sh` exactly as committed, against One Pace, does not merely fail to add repairs —
**it removes the repairs already in the shipped track and reverts the episode to raw ASR.**

Reproduced accidentally on 2026-08-30 against S31E24: `targets=144 repaired=0
skipped_no_ref=144`, and the sidecar came back as `our mods will never give up There's a`
where the shipped track had `Our mods will never give up. There's a fire...`. Restored with
`review_apply.apply_episode`; no video had been re-muxed, so nothing was lost. Re-run with
`REPAIR_UNANCHORED=1`: `targets=144 repaired=13 skipped_no_ref=0`.

The same run also discards any human text `review_apply` wrote — see
`20260830-a-skipped-card-never-reaches-the-decision-store.md`.

## The decision this needs

The flag defaults closed for a reason the docstring states well: glossary-only repair
hallucinates names, the gate-open evidence is "ONE episode of ONE show on ONE model", and
turning it on is meant to be a deliberate act. That reasoning is sound and is NOT what this
todo proposes to overturn.

What is wrong is that the deliberate act left no trace, so the repo cannot reproduce the
library and the committed scripts are destructive against it. Options:

- **(a)** a per-show setting (the glossary file already carries per-show config) so One Pace
  declares that it is unanchored-repair-enabled and no global flag is needed;
- **(b)** set it in `gen_loop.sh`/`merge_pass.sh` with the measurement in a comment, keeping
  one global default but making it visible;
- **(c)** refuse rather than silently rebuild: if a run would skip EVERY target on an episode
  that has prior repairs, abort that episode and log it, so a misconfigured pass cannot
  quietly revert the library.

(c) is worth doing WHATEVER is chosen for the flag itself — it is the guard that makes the
failure loud, and it is independent of the policy question.

## Acceptance criteria

- [ ] A merge pass run from the committed scripts, with no hand-set environment, does not
      reduce the repair count of any already-repaired episode.
- [ ] Asserted on a fixture: an episode with prior repairs, no reference track, and the gate
      closed — the run must not silently emit raw ASR over it.
- [ ] Whatever reproduces the current One Pace behaviour is recorded in a committed file, not
      in an operator's shell history.
- [ ] `skips_unanchored`'s docstring stays the authority on WHY the gate defaults closed; this
      changes how the decision is recorded, not the decision.
